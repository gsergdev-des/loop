## Контекст

Нужен подписанный release-APK для установки на один телефон (R16). Ключа подписи у сборщика нет, он принадлежит пользователю и не должен попадать в репозиторий. Неподписанный APK на Android не ставится.

## Решение

`signingConfigs.release` читает `keystore.properties` из корня проекта (`storeFile`, `storePassword`, `keyAlias`, `keyPassword`). Если файла нет, release подписывается стандартным debug-ключом, а Gradle печатает предупреждение со ссылкой на README. Файл, `*.jks` и `*.keystore` перечислены в `.gitignore`.

## Почему

- Рассмотрено: хранить свой ключ в репозитории. Отвергнуто: ключ и пароли в репозиторий не попадают никогда.
- Рассмотрено: падать, пока нет `keystore.properties`. Отвергнуто: тогда сборка ни у кого не пройдёт без подготовки, а проверочная команда (`assembleRelease`) должна быть зелёной сразу.
- Рассмотрено: выдавать неподписанный APK. Отвергнуто: Android его не установит.
- Откат на debug-ключ даёт устанавливаемый файл, а настоящий ключ подключается по README одной командой `keytool` без правок кода.

## Последствия

- APK, подписанный debug-ключом, и APK, подписанный своим ключом, имеют разные подписи: переход с одного на другой требует удалить приложение (данные DataStore теряются).
- Debug-ключ общеизвестен, поэтому такой APK нельзя считать доверенным за пределами личного использования. Публикация в Google Play этим решением не поддерживается.
- Пароли лежат на диске в открытом виде в `keystore.properties`; безопасность держится на том, что файл не коммитится.
- Предупреждение сборки легко не заметить: пользователь может долго жить на debug-подписи.
